# Peerward

[English](README.md) | [简体中文](README.zh-CN.md)

可直接复制使用：[中文提示词库](PROMPTS.zh-CN.md) | [English Prompt Library](PROMPTS.md)

**引导每一版稿件走向同行评审。**

Peerward 是一个覆盖科研论文全生命周期的证据驱动 AI 写作导师。它可以指导学生从研究结果形成初稿，提升科学论证和数学表达，评价论文质量，生成专业模拟审稿意见，制定真实返修方案，并核验回复信及正文修改是否真正兑现。

Peerward 由 *peer* 与表示方向的 *-ward* 构成，表示把每一版稿件逐步提升到导师审阅和同行评审所要求的水平，但不承诺科学结论必然正确或论文必然录用。

它主要面向控制、优化、多智能体系统、无人系统和 AI for Control 等研究方向。Peerward 关注的不是简单润色句子，而是解释论文为什么需要这样修改，以及修改如何降低科学性、论证或表达方面的风险。

## 安装

将 `peerward` 目录复制到 Codex 的 skills 目录，然后使用以下形式调用：

```text
$peerward 分析这些审稿意见及其对应的论文段落。
```

可以提供研究笔记、论文段落、审稿意见、回复信、Git 历史或不同版本的 LaTeX 文件。Peerward 既可以辅助从零设计论文结构，也可以诊断已有稿件；证据不足时会明确标记未知项，而不会虚构信息。

## 知识模式

- 学生初稿指导与多轮导师式交互；
- 科研问题与论证设计；
- 论文整体结构与章节架构；
- 数学定义、符号、定理陈述和证明；
- 面向非英语母语作者的科研英语；
- 基于证据的论文质量评价；
- 专业模拟审稿；
- 审稿驱动的论文修改和回复质量核验。

其中的写作知识是对经典科研写作和数学写作资料的原创归纳。仓库记录参考资料名称以说明知识来源，但不收录受版权保护的教材原文。

## 方法使用说明

调用 `$peerward` 时，请同时提供当前可用的证据以及你需要作出的决定。输入可以是研究问题、论文段落、LaTeX 源码、审稿意见、回复信或 Git 版本范围。保密材料应始终保留在本地工作区，不要粘贴到公开 Issue 或提交记录中。

Peerward 按以下顺序分析论文：

1. 科研问题和读者需求；
2. 核心主张、理由、证据、假设和局限；
3. 论文与章节的整体架构；
4. 数学定义、符号、定理和证明；
5. 段落信息流和句子层面的英语表达；
6. 审稿人关注点、修改行动、验证证据和回复策略。

该方法记录以下因果链：

```text
审稿意见 → 潜在真实关注点 → 修改策略
→ 实际或拟议修改 → 验证证据 → 可迁移经验
```

因此，它解释的是修改背后的**原因**，而不只是记录“增加了文字、理论或实验”。

### 示例提示词

完整的项目上下文、论文设计、审稿回复、Git 修改史、数学审计、隐私审计和 GitHub 维护提示词见[中文提示词库](PROMPTS.zh-CN.md)。

在写作前规划论文：

```text
$peerward 将这些研究笔记整理为主张地图和论文大纲。
```

修改论文段落：

```text
$peerward 诊断这段引言和定理部分在科学论证与数学表达方面的问题。先处理结构问题，再处理语言润色。
```

回应审稿意见：

```text
$peerward 结合论文和回复信分析这些审稿意见。对每条意见提出修改方案，判断是否需要补充理论、实验或对比，并给出回复策略。
```

学习版本修改历史：

```text
$peerward 对比这些 LaTeX 版本或 Git commits，识别关键科研写作决策，并提炼 3–10 条可迁移经验。
```

可能的输出包括：主张地图、修改优先级、章节级修改行动、理论/实验/对比判断、回复信建议、证据缺口，以及在案例证据充分时生成的 `case_summary.md`。

## 隐私边界

本仓库仅包含通用工作规则和合成教学数据。请勿提交未公开论文、真实审稿意见、回复信、投稿编号、个人信息、本地绝对路径、API 凭据或私有 Git 历史。详见 [PRIVACY.md](PRIVACY.md)。

关于学生署名责任、保密审稿、AI 使用披露、评分边界和人工责任，详见 [负责任使用规范](RESPONSIBLE_USE.zh-CN.md)。

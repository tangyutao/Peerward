# Multi-Round Mentor Interaction

Use this reference when supervising a student across multiple drafting or revision rounds. The purpose is cumulative learning and manuscript progress, not endless rewriting.

## Persistent mentor state

Maintain a compact state record when the user authorizes a persistent file:

- paper goal and current stage;
- main claim and contribution chain;
- verified evidence and unresolved gaps;
- current quality-gate status;
- decisions already made and their reasons;
- recurring student difficulties;
- current assignment and acceptance criteria;
- next milestone;
- evidence paths without private absolute paths in shared outputs.

Do not store personality judgments or unnecessary personal data. Record observable writing behavior and task performance.

## One mentoring round

### 1. Re-establish the goal

State the current artifact, intended reader decision, and one learning objective.

### 2. Verify the previous assignment

Compare the student's new version with the prior artifact. Record:

- completed;
- partially completed;
- not demonstrated;
- new regression.

Do not accept “I revised it” without checking the artifact.

### 3. Diagnose the highest-leverage issue

Choose the earliest upstream failure:

research question → claim/evidence → formulation → architecture → mathematics → paragraph flow → language

Do not spend the round polishing downstream prose when an upstream issue remains.

### 4. Teach through guided action

Use:

question → hint → scaffold → student attempt → evidence-based feedback

Provide a candidate rewrite only when it teaches a visible principle or the user requests direct editing.

### 5. Assign a bounded task

Specify:

- artifact to return;
- constraints;
- acceptance criteria;
- verification method;
- what not to change;
- deadline only if the user supplies one.

### 6. Close the loop

Ask the student to state:

- what changed;
- why it changed;
- what evidence now supports it;
- what remains uncertain;
- where the same lesson applies next.

Update mentor state using observed results.

## Milestone gates

### Gate A: research-to-paper readiness

Pass when the research question, principal claim, baseline, mechanism, evidence, and limitations can be stated without contradiction.

### Gate B: complete first draft

Pass when every section has a defined role and all central claims have either evidence or an explicit placeholder.

### Gate C: scientific revision

Pass when critical correctness, formulation, and evidence issues are resolved or transparently bounded.

### Gate D: mock review

Pass when independent mock review produces no unresolved critical blocker and major comments have an action plan.

### Gate E: submission readiness

Pass when manuscript, supplementary material, metadata, declarations, and venue requirements are consistent.

### Gate F: response readiness

Pass when every reviewer comment has a verified response and actual manuscript change or a reasoned, evidenced disagreement.

## Adapt to student maturity

- **Novice:** one upstream issue per round, explicit scaffolds, frequent explanation checks.
- **Developing:** two or three linked issues, student proposes actions before receiving solutions.
- **Advanced:** independent diagnosis first, mentor challenges assumptions and evidence boundaries.
- **Near submission:** switch from teaching breadth to risk triage and verification.

Do not infer maturity from seniority. Base support level on demonstrated work.

## Stop and escalation conditions

Escalate to a human domain expert when:

- theorem correctness cannot be established from available evidence;
- research originality or ethical approval is disputed;
- experimental data integrity is uncertain;
- author contribution or conflict-of-interest decisions are required;
- journal policy controls AI use or confidential peer review.

A mentor-like tool can replace repetitive supervision steps, but not scientific accountability.
